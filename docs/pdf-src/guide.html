Pourquoi ? / Why? La Time Capsule ne partage son disque qu'en AFP, un protocole qu'Apple abandonne : macOS 27 ne saura plus s'y connecter. Un Raspberry Pi sert de pont : il monte la capsule en AFP et la repartage en SMB, que le Mac comprend toujours. / The Time Capsule only shares its disk over AFP, which Apple is dropping: macOS 27 can no longer connect to it. A Raspberry Pi acts as a bridge: it mounts the capsule over AFP and re-shares it over SMB, which the Mac still understands.

FRANÇAIS

1. Ce qu'il vous faut

  • Un Raspberry Pi 4 (2 Go de RAM ou plus), son alimentation, une carte microSD, un câble Ethernet vers votre box (le Wi-Fi n'est pas assez stable pour ce rôle).
  • Votre Time Capsule, branchée en Ethernet à la box.
  • Un Mac ou un PC Windows pour lancer l'installation.
  • Le mot de passe du disque de la Time Capsule.

2. Préparer le Raspberry Pi

  1. Installez Raspberry Pi Imager (raspberrypi.com/software) sur votre ordinateur.
  2. Choisissez Raspberry Pi OS Lite (64-bit), puis les réglages avancés (engrenage) : activez SSH et choisissez un nom d'utilisateur et un mot de passe.
  3. Écrivez sur la carte, insérez-la dans le Pi, branchez Ethernet puis l'alimentation. Attendez 2 minutes.

Le Pi s'appelle en général raspberrypi.local. Sinon, son adresse IP figure dans l'interface de votre box.

3. Préparer la Time Capsule

  1. Dans Utilitaire AirPort (Mac, iPhone ou iPad) : sélectionnez la capsule › Modifier › onglet Disques.
  2. Renommez le disque sans espaces (ex. AirPortTimeCapsule) : le client AFP ne gère pas les espaces. Cliquez Mettre à jour (≈ 2 min).
  3. Notez le mot de passe du disque et l'adresse IP de la capsule.
Nom d'utilisateur AFP. Selon les réglages, la capsule peut exiger un nom d'utilisateur en plus du mot de passe. Pour le retrouver : sur un Mac qui s'y connecte déjà, ouvrez Trousseau d'accès, cherchez le nom de votre capsule et lisez le champ Compte. Si votre capsule n'en demande pas, laissez vide.

4. Installer en un clic

Téléchargez le zip correspondant à votre ordinateur depuis la page GitHub du projet (dossier installers) :

6. Mots de passe : où vont-ils ?

  • Jamais en clair sur le disque, dans un script, dans une unité systemd ni sur une ligne de commande visible dans ps.
  • Le mot de passe de la capsule est chiffré par systemd-creds et déchiffré en mémoire seulement, pour le service de montage. Il est transmis au client AFP par l'entrée standard.
  • Samba ne conserve qu'une empreinte du mot de passe (comportement normal).
  • Limite honnête : sur un Pi (sans puce TPM), la clé de chiffrement est sur la même carte SD. Cela protège des lectures accidentelles, copies de fichiers et captures d'écran, pas d'un attaquant qui aurait la carte et les droits root. Le mode « mémoire seulement » existe pour qui n'accepte pas ce compromis.
  • Changer le mot de passe : sudo timecapsule-ctl set-password. Changer l'utilisateur AFP : sudo timecapsule-ctl set-user NOM.

7. Configurer Time Machine sur le Mac

  1. Réglages Système › Général › Time Machine › bouton +.
  2. Choisissez TimeMachine sur raspberrypi.local (le nom de votre Pi).
  3. Entrez l'utilisateur et le mot de passe Samba.
Une seule destination. Si la capsule figure aussi comme destination directe (AFP), Time Machine y écrira dans le même fichier de sauvegarde. Avec macOS 27 cette destination disparaîtra de toute façon : gardez uniquement celle du Pi.

8. Protections et journaux

CoucheRôleFréquence
1. Keepalive TCP noyauDétecte une connexion morte en ≈ 2 minpermanent
2. Sonde en lecture seuleVérifie le montage (lecture), la capsule, et mesure l'état complet. N'écrit pas chaque minute : le disque de la capsule s'endort après ≈ 1 min, y écrire en permanence l'empêcherait de dormir. Test d'écriture toutes les 6 h seulementchaque minute
3. WatchdogSauve un dossier d'incident, coupe Samba, débloque, remonte, vérifie, relance Sambachaque minute

Ces tâches sont des timers systemd (et non cron) : ils ne se chevauchent jamais, sont tués après un délai, et ne peuvent pas s'empiler. Samba ne démarre que si la capsule est montée. Une panne simulée (client AFP tué) est réparée en ≈ 80 secondes.

sudo timecapsule-ctl status      # état, depuis quand, derniers événements
sudo timecapsule-ctl report      # historique : durées connecté, causes, ce qui a changé
sudo timecapsule-ctl logs -f     # journal en direct
sudo timecapsule-ctl incidents   # dossiers d'incident
sudo timecapsule-ctl audit       # vérifications de sécurité

À chaque changement d'état, le journal (/var/log/timecapsule/events.log) garde : la durée de l'état précédent (donc combien de temps la connexion a tenu), les causes, les champs qui ont changé et les instantanés avant / après (montage, latence, capsule, client AFP, Samba, réseau, charge, espace libre…). Il note aussi chaque sauvegarde vue par le pont (début, durée, volume transféré) et chaque connexion au partage : timecapsule-ctl report les résume par jour et signale les intervalles de plus de 90 min. Sur le Mac, bash tools/install-mac-logger.sh conserve les décisions de Time Machine (que le système n'efface qu'après ≈ 19 h).

10. Mettre à jour, désinstaller

Mettre à jour : relancez simplement l'installateur (nouveau zip ou git pull puis sudo bash install.sh) : il est sans danger à relancer.

Désinstaller :

sudo systemctl disable --now timecapsule-keepalive.timer timecapsule-watchdog.timer timecapsule-mount.service
sudo rm -rf /etc/systemd/system/timecapsule-* /etc/systemd/system/smbd.service.d/timecapsule.conf \
  /etc/timecapsule /usr/local/lib/timecapsule /usr/local/bin/timecapsule-* /usr/local/bin/tc-ctl
sudo systemctl daemon-reload

Puis supprimez les deux lignes include = /etc/samba/timecapsule-… de /etc/samba/smb.conf (une sauvegarde smb.conf.pre-timecapsule existe) et redémarrez Samba.

11. À savoir

  • Une première sauvegarde complète est longue (plusieurs jours pour un disque de 1 à 2 To : de l'ordre de 10 à 20 Go/h observés, car tout passe par le pont AFP/FUSE). Les sauvegardes suivantes ne copient que les nouveautés et prennent quelques minutes.
  • Gardez 100 Go libres sur la capsule, et réglez une taille maximale inférieure à celle du disque.
  • Le Pi doit être en Ethernet. Si vous gardez aussi le Wi-Fi actif, notez que le Pi aura deux adresses.
  • Si un assistant IA vous guide, ne lui donnez jamais vos mots de passe : saisissez-les vous-même.

ENGLISH

1. What you need

  • A Raspberry Pi 4 (2 GB RAM or more), its power supply, a microSD card and an Ethernet cable to your router (Wi-Fi is not stable enough for this role).
  • Your Time Capsule, plugged into the router with Ethernet.
  • A Mac or a Windows PC to run the installation.
  • The Time Capsule disk password.

2. Prepare the Raspberry Pi

  1. Install Raspberry Pi Imager (raspberrypi.com/software) on your computer.
  2. Pick Raspberry Pi OS Lite (64-bit), then the advanced settings (gear icon): enable SSH and choose a username and password.
  3. Write the card, put it in the Pi, plug in Ethernet then power. Wait 2 minutes.

The Pi is usually reachable as raspberrypi.local. Otherwise find its IP address in your router's interface.

3. Prepare the Time Capsule

  1. In AirPort Utility (Mac, iPhone or iPad): select the capsule › Edit › Disks tab.
  2. Rename the disk without spaces (e.g. AirPortTimeCapsule): the AFP client cannot handle spaces. Click Update (≈ 2 min).
  3. Note the disk password and the capsule's IP address.
AFP username. Depending on its settings, the capsule may require a username as well as the password. To find it: on a Mac that already connects to it, open Keychain Access, search for your capsule's name and read the Account field. If your capsule does not ask for one, leave it empty.

4. One-click install

Download the zip for your computer from the project's GitHub page (installers folder):

6. Passwords: where do they go?

  • Never in clear text on disk, in a script, in a systemd unit or on a command line visible in ps.
  • The capsule password is encrypted by systemd-creds and decrypted in memory only, for the mount service. It is handed to the AFP client through standard input.
  • Samba only keeps a hash of its password (normal behaviour).
  • Honest limit: on a Pi (no TPM chip) the encryption key lives on the same SD card. It protects against accidental reads, file copies and screenshots, not against an attacker holding the card and root. The "RAM only" mode exists for anyone who cannot accept this trade-off.
  • Change the password: sudo timecapsule-ctl set-password. Change the AFP username: sudo timecapsule-ctl set-user NAME.

7. Set up Time Machine on the Mac

  1. System Settings › General › Time Machine › + button.
  2. Pick TimeMachine on raspberrypi.local (your Pi's name).
  3. Enter the Samba username and password.
One destination only. If the capsule is also listed as a direct (AFP) destination, Time Machine will write to the same backup file through two paths. With macOS 27 that destination goes away anyway: keep only the Pi's.

8. Protection and logs

LayerRoleFrequency
1. Kernel TCP keepaliveDetects a dead connection in ≈ 2 minpermanent
2. Read-only probeChecks the mount (read), the capsule, and records the full state. Does not write every minute: the capsule's disk sleeps after ≈ 1 min, writing constantly would keep it awake. Write test every 6 h onlyevery minute
3. WatchdogSaves an incident report, stops Samba, unblocks, re-mounts, verifies, restarts Sambaevery minute

These jobs are systemd timers (not cron): they never overlap, are killed after a timeout, and cannot pile up. Samba only starts when the capsule is mounted. A simulated crash (AFP client killed) is repaired in ≈ 80 seconds.

sudo timecapsule-ctl status      # state, since when, latest events
sudo timecapsule-ctl report      # history: connected durations, causes, what changed
sudo timecapsule-ctl logs -f     # live log
sudo timecapsule-ctl incidents   # incident reports
sudo timecapsule-ctl audit       # security checks

At every state change the log (/var/log/timecapsule/events.log) keeps: the duration of the previous state (how long the connection held), the causes, the fields that changed and the before / after snapshots (mount, latency, capsule, AFP client, Samba, network, load, free space…). It also records every backup seen by the bridge (start, duration, data moved) and every connection to the share: timecapsule-ctl report summarises them per day and flags gaps longer than 90 min. On the Mac, bash tools/install-mac-logger.sh keeps Time Machine's decisions (which the system erases after ≈ 19 h).

10. Update, uninstall

Update: simply run the installer again (new zip, or git pull then sudo bash install.sh): it is safe to re-run.

Uninstall:

sudo systemctl disable --now timecapsule-keepalive.timer timecapsule-watchdog.timer timecapsule-mount.service
sudo rm -rf /etc/systemd/system/timecapsule-* /etc/systemd/system/smbd.service.d/timecapsule.conf \
  /etc/timecapsule /usr/local/lib/timecapsule /usr/local/bin/timecapsule-* /usr/local/bin/tc-ctl
sudo systemctl daemon-reload

Then remove the two include = /etc/samba/timecapsule-… lines from /etc/samba/smb.conf (a smb.conf.pre-timecapsule backup exists) and restart Samba.

11. Good to know

  • A first full backup is slow (days for a 1–2 TB disk: roughly 10 to 20 GB/h observed, since everything goes through the AFP/FUSE bridge). Later backups only copy what changed and take minutes.
  • Keep 100 GB free on the capsule, and set a maximum size below the disk size.
  • The Pi must be on Ethernet. If you also keep Wi-Fi on, the Pi will have two addresses.
  • If an AI assistant guides you, never give it your passwords: type them yourself.
